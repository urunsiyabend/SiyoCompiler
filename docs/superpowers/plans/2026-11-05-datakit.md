# DataKit / Siyo 0.10.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build DataKit (`projects/datakit`) and release Siyo 0.10.0 from what it needs: generic call results that keep their type, generic structs, `strings.formatFloat`/`isFloat` and `std/csv`.

**Architecture:** Compiler work goes into the string-typed generic machinery. That means `TypeResolver.declaredTypeNameOf`, plus a unifier over type-name strings in `Binder`, and struct type parameters on `StructSymbol`. The stdlib additions are Siyo modules, with `SiyoRuntime` helpers where precision matters. DataKit is a Siyo-only multi-module CLI. Its end-to-end checks run in Java against an independent oracle.

**Tech Stack:** Java 21, Maven, ASM, JUnit 5; Siyo.

**Spec:** `docs/superpowers/specs/2026-11-05-datakit-design.md`

## Global Constraints

- Every change preserves existing behaviour, and the full `mvn clean verify` stays green.
- Each compiler or stdlib fix gets a regression test that asserts the same output on both backends (`run` and `interpret`).
- An apparent limitation is first checked against the 0.9.0 jar (`/tmp/dk-ref/siyo-0.9.0.jar`). A new silent regression is fixed, never deferred.
- App code imports no Java class, and nothing in it recurses to a depth taken from the input.
- No larger stacks, and resources stay bounded: test fixtures are under 1 MB and generated datasets are capped at 2,000 rows.
- Commits use `git -c user.name="Siyabend Ürün" -c user.email=urunsiyabend@gmail.com`. Nothing is pushed, merged or tagged.

## Review Focus

1. A capture walk or spawn check misses a new node field. New bound nodes need no new field, and new struct-literal type info rides on existing nodes; `CaptureTraversalTest`'s field audit must still pass.
2. A generic struct passes through a module boundary. `Group<T>` is declared in `pipeline.siyo` and used from `main.siyo`, so a test covers an imported generic struct.
3. An existing `--out` file is clobbered, or the output path equals the input path. The E2E test checks the file bytes are unchanged and the exit status is 2.
4. CSV quoting edge cases: a quoted empty field, `""` inside quotes, CRLF inside quotes, a trailing newline or none. Covered by the `csv_test.siyo` unit tests and by the E2E oracle.
5. Floats: `formatFloat` on negatives, on values that round up to the next order (`9.995` to 2 places), on NaN, and on `-0.0`. These are unit-tested in the regression test.

### Task 3: `strings.formatFloat`, `strings.isFloat` (G3, G4)

**Files:** `SiyoRuntime.java` (`formatFloat(double,int)`, `isFloat(String)`), `std/strings.siyo`. Test: `DataKitRegressionTest`.

- [ ] Write tests with these exact expectations:

  | Call | Result |
  |------|--------|
  | `formatFloat(2.0/3.0, 2)` | `"0.67"` |
  | `formatFloat(2.675, 2)` | `"2.68"` |
  | `formatFloat(9.995, 2)` | `"10.00"` |
  | `formatFloat(-1.5, 0)` | `"-2"` |
  | `formatFloat(-0.0, 1)` | `"0.0"` |
  | `formatFloat(1.0/0.0, 2)` | `"Infinity"` |
  | `formatFloat(0.0/0.0, 2)` | `"NaN"` |
  | `formatFloat(x, 18)` | raises |

  `isFloat` accepts `"1"`, `"-2.5"`, `"1e3"` and `".5"`. It rejects `""`, `" 1"`, `"NaN"`, `"Infinity"`, `"1f"`, `"0x1p3"`, `"1e"` and `"1.2.3"`. Note that `"-0"` is accepted.
- [ ] Implement with `BigDecimal(Double.toString(x)).setScale(d, HALF_UP)` and normalise negative zero; `isFloat` uses a regex `-?(\d+\.?\d*|\.\d+)([eE][+-]?\d+)?` plus a finiteness check. Commit.
